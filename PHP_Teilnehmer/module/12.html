Datenbankzugriff als weiterer Verarbeitungsschritt

PHP nimmt die Anfrage entgegen, stellt eine Datenbankverbindung her und verarbeitet das Ergebnis einer SQL-Abfrage.

  • Die Unterlage empfiehlt MySQLi beziehungsweise PDO statt der alten mysql-Schnittstelle.
  • Für diesen Kurs verwenden wir MySQLi.
  • Die lokale Konfiguration enthält keine produktiven Zugangsdaten.
Beispiel lesen
$db = mysqli_connect($host, $user, $passwort, $datenbank);
mysqli_set_charset($db, "utf8mb4");
Merke / Beobachtung: Host, Benutzer, Kennwort und Datenbank stammen aus einer eigenen lokalen Konfiguration.

Prozedural und objektorientiert

MySQLi bietet beide Aufrufstile. Der Kurs nutzt im Pflichtbeispiel die prozedurale Variante; die objektorientierte Form wird entsprechend der Quelle zum Vergleich gezeigt.

  • Prozedural: Verbindung als Argument.
  • Objektorientiert: Methodenaufruf an Verbindung beziehungsweise Ergebnis.
  • Eigene PHP-Klassen sind als optionaler Quellenabschnitt 26–27 markiert, nicht im Grundlagenquiz vorausgesetzt.
Beispiel lesen
// prozedural
mysqli_close($db);
// entsprechende objektorientierte Schreibweise
$db->close();
Merke / Beobachtung: Keine Vermischung von zwei Schreibstilen innerhalb eines kleinen Beispiels nötig.

Eine Hilfsfunktion verwenden

Der wiederkehrende Verbindungsaufbau kann in einer gesonderten Datei gebündelt werden. Das entspricht dem Utility-Beispiel der Unterlage.

  • require_once bindet die Hilfsdatei ein.
  • Die Funktion liefert die Verbindung zurück.
  • Konfiguration und Darstellung bleiben getrennt.
Beispiel lesen
require_once __DIR__ . "/db.php";
$db = db_connect();
Merke / Beobachtung: Das vollständige Beispiel liegt in backend/db.php.

Werte an vorbereitete Abfragen binden

Korrektur K5: Der direkt in SQL kopierte Formularwert der Folien 30–31 wird durch einen gebundenen Parameter ersetzt. Prepared Statements sind bereits auf Folie 24 genannt.

  • SQL-Struktur und eingegebener Wert bleiben getrennt.
  • Der Platzhalter steht dort, wo der Datenwert benötigt wird.
  • Eine fachliche Prüfung zulässiger Ziele bleibt trotzdem sinnvoll.
Beispiel lesen
$sql = "SELECT ziel, preis_cent FROM angebote WHERE ziel = ?";
$stmt = mysqli_prepare($db, $sql);
mysqli_stmt_bind_param($stmt, "s", $ziel);
mysqli_stmt_execute($stmt);
Merke / Beobachtung: Der Zielwert wird nicht durch Zeichenkettenverkettung in den SQL-Code geschrieben.

Treffer, leere Liste und Fehler unterscheiden

Eine ausgeführte SELECT-Abfrage kann passende Datensätze oder keine Treffer liefern. Ein technischer Fehler ist ein anderer Zustand.

  • Ergebnisse in verständliche HTML-Inhalte übertragen.
  • E1: Auch Werte aus einer Datenbank werden beim HTML-Ausgeben maskiert.
  • Interne Fehlerdetails nicht unkontrolliert als Bedienhinweis ausgeben.
Beispiel lesen
Abfrage erfolgreich + Treffer → Ergebnistabelle
Abfrage erfolgreich + keine Treffer → „Keine Angebote“
Technischer Fehler → passende Fehlermeldung
Merke / Beobachtung: Keine dieser Aussagen bedeutet „Buchung abgeschlossen“.

Die Vorlage nennt Anmeldung, Reisesuche, Ergebnisse und Buchungsabschluss als Projektabschnitte. Unser ausgearbeitetes Kursprojekt konzentriert sich auf die vollständige Suchstrecke.

  • index.php: Auswahl und Anfrage.

  • Original-Aufträge zu login.php, buchung.php und buchabschl.php bleiben sichtbar als weiterführende, hier nicht implementierte Projektstufen.
Beispiel lesen
Formular → Prüfung → Verbindung → SELECT mit Parameter
→ Daten lesen → HTML-Tabelle → Auswahl ändern
Merke / Beobachtung: Kein vorgetäuschter Login, keine Buchung und keine Zahlung.
