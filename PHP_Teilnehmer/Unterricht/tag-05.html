Kurz erklärt

Die vorhandenen Cookie- und Session-Webvarianten enthalten Erklärungen, Schrittsimulationen, fertige Demos, Aufgabenblätter und Startdateien. Bearbeite heute je eine kleine Aufgabe vollständig. Weitere Aufgaben bleiben als Übungsreserve erreichbar.

Vergleiche in den Entwicklerwerkzeugen Browser-Speicher, Request-Header und Response-Header. Für einen unabhängigen Session-Test verwende ein getrenntes Browserprofil. Eine Cookie-Einstellung und ein serverseitig gespeicherter Formularentwurf haben unterschiedliche Aufgaben.

Cookie
Ein Browser speichert einen kleinen Wert und sendet ihn bei passenden Folgeanfragen mit. Der Server setzt ihn über Set-Cookie; die Anfrage trägt ihn im Cookie-Header. Cookie-Daten sind veränderbare Eingaben.
setcookie und $_COOKIE
setcookie setzt einen Antwort-Header. $_COOKIE enthält dagegen die Werte der eingehenden Anfrage. Ein neu gesetzter Wert erscheint dort erst bei einem späteren passenden Request.
Session
Im Kurs speichert PHP die Nutzdaten serverseitig. Der Browser trägt normalerweise die Session-ID in einem Cookie. Vor dem Zugriff auf $_SESSION wird auf jeder beteiligten Seite session_start aufgerufen.
Speichern und Lesen
Eine Zuweisung in $_SESSION ist im selben Skript sofort lesbar. Cookie- oder Session-Funktionen, die Header senden, gehören vor die HTML-Ausgabe. Eine Session benötigt weder OOP noch eine Datenbank.
Löschen
Ein Cookie wird mit gleichem Namen und Gültigkeitsbereich und einer vergangenen Ablaufzeit gelöscht. unset entfernt einen Session-Schlüssel. session_destroy allein leert weder das aktuelle PHP-Array noch das Browser-Cookie.
Grenzen
Ein neues Browser-Tab ist keine unabhängige Session. Browser-Schließen ist kein zuverlässiger Logout-Test. Die Übungsbeispiele sind keine Anmeldung und verwenden nur fiktive Daten.

Kleines Beispiel lesen

<?php
declare(strict_types=1);
session_start(); // vor der HTML-Ausgabe
if (!isset($_SESSION["thema"])) {
    $_SESSION["thema"] = "PHP";
}
echo htmlspecialchars($_SESSION["thema"], ENT_QUOTES, "UTF-8");

Erst die Wirkung vorhersagen, dann ausführen oder im Browser untersuchen. Das Beispiel erklärt ein Prinzip; es ist keine Lösung der folgenden Aufgabe.

Selbst umsetzen

Nutze die vorbereiteten Cookie- und Session-Aufgaben. Merke eine erlaubte Anzeigeeinstellung per Cookie. Speichere einen geprüften Alias in einer Session und lies ihn auf einer zweiten Seite. Teste fehlende oder manipulierte Eingaben und das Überschreiben eines gespeicherten Werts. Lösche das Cookie einmal in den Browserwerkzeugen. Erprobe unset und das vollständige Session-Beenden anschließend in der verlinkten Session-Demo; die Startaufgabe 01 verlangt zunächst nur Speichern und Lesen. Ergänze anschließend höchstens eine dieser Funktionen in dein Formularprojekt.

Abgabe: eigene Dateien, kurze Erklärung und mindestens ein Normal-, Fehl- und Grenzfall mit Soll/Ist-Vergleich.
