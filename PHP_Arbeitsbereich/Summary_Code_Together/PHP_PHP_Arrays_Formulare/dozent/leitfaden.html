Der rote Faden für die Demonstration.

Erst zwei Dateien verstehen, dann drei Seiten verbinden. Hilfsfunktionen schrittweise erschließen.

PhaseZeitvorschlagAktion
Arrays und Code lesen45 MinutenListen, Schlüssel, verschachtelte Kataloge; Array-Labor.
Kontrollstrukturen und Pseudocode45 MinutenSchleifen unterscheiden, Rechnung vorhersagen.
Mini-Demo30 MinutenStatisches HTML absenden, $_POST und Ausgabe beobachten.
Mehrseitige Demo60 MinutenOptionen generieren, Hidden-Transport, Änderung und Rückweg.
Üben und testen75 MinutenAusgewählte Aufgaben, Fehlerfälle und Soll-/Ist-Auswertung.
Session-/Cookie-Ausblick15 MinutenProblem des expliziten Transports zusammenfassen.

Summe: 270 Minuten = sechs UE. Pausen kommen hinzu. Die Aufgabenzeiten sind Alternativen für Vertiefung, nicht zusätzlich vollständig in diese Planung eingerechnet.

Konkreter Live-Durchlauf

  • Server starten, Kursübersicht öffnen und Mini-Demo aufrufen.
  • Im Mini-Formular Paris + Museum + Tour wählen; Nachricht zweizeilig eingeben.
  • Im Netzwerkbereich des Browsers den POST und die übertragenen Feldnamen untersuchen.
  • In der Mehrseiten-Demo Paris, 2 Personen, Museum + Tour, Frühstück wählen: 508,00 € auf Seite 2.
  • Verpflegung auf Halbpension ändern: 544,00 € auf Seite 3.
  • Bearbeiten klicken: neu übertragene Angaben sind wieder ausgewählt.
  • Neue leere Auswahl öffnen und Seite 3 direkt aufrufen: ohne neuen POST keine Reise.
  • Hidden-Feld im eigenen lokalen Browser verändern: unbekannte ID ablehnen, bekannte ID als neue Auswahl auswerten.

Häufige Missverständnisse

AussageKlärung
„POST merkt sich das Array.“Nein, POST beschreibt die aktuelle Anfrage.
„Mit require bleibt meine Auswahl erhalten.“Nur statischen Katalogcode neu laden; kein Benutzerzustand.
„Eine Textarea rendert HTML.“Nein, sie enthält Text. Strukturierte Formatierung außerhalb erzeugen.
„Ein Hidden-Feld ist sicher.“Nein, der Browser kann es verändern.
„selected=false deaktiviert die Auswahl.“Das Boolean-Attribut muss fehlen, um nicht zu gelten.
„Kein Extra ist ein Fehler.“Das Feld darf fehlen; der Empfänger verwendet eine leere Liste.
Abgrenzung: lokale, nicht persistierende Demo. Kein produktiver Buchungsabschluss, keine Authentifizierung und kein CSRF-geschützter Schreibvorgang. Die Tests belegen nur die dokumentierten Unterrichtsfunktionen.

Bekannte Umgebungsgrenzen

Unter Linux mit PHP und Chromium geprüft; Details siehe Testprotokoll. Windows-CMD und XAMPP sind Startwege für deinen Rechner und müssen dort mit den vorhandenen Installationspfaden passen. Die Anwendung nutzt keine Composer-Pakete und keine Datenbank.
