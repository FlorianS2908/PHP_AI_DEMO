Cookies: Der Browser merkt sich einen Wert.

PHP sendet die Anweisung. Der Browser speichert sie – sofern erlaubt – und schickt passende Cookies bei späteren Anfragen zurück. [4]

01 / Architektur

Zwei Richtungen. Zwei unterschiedliche Header.

Server → Browser

setcookie() erzeugt einen Set-Cookie-Antwort-Header. Er bittet den Browser, einen Wert zu speichern, zu ändern oder zu löschen.

Browser → Server

Ein späterer Request sendet passende Werte im Cookie-Header. PHP stellt diese eingehenden Daten in $_COOKIE bereit.

Passend bedeutet unter anderem: richtiger Host, passender URL-Pfad, noch gültig und vom Browser erlaubt. [1] [2] [5]

Der wichtigste Unterschied: $_POST enthält Formulardaten dieses POST-Aufrufs. $_COOKIE enthält die mit dieser Anfrage angekommenen Cookie-Daten. Ein neu ausgeführtes setcookie() aktualisiert dieses Array nicht. [1]

02 / Syntax

Drei Operationen reichen für den Einstieg.

Setzen oder ändern

Erst die Formulardaten prüfen. Dann den Cookie-Header senden und anschließend weiterleiten. Die 303-Rückleitung erzeugt hier einen neuen GET-Aufruf. [1] [3] [6]

// Vor jeder HTML-Ausgabe; $sprache wurde bereits geprüft.
setcookie("PHP_demo_sprache", $sprache, [
    "expires" => time() + 3600, // eine Stunde ab jetzt
    "path" => "/PHP_AI_DEMO/PHP_Arbeitsbereich/cookies/demo/",
    "secure" => false,        // nur lokale HTTP-Übung
    "httponly" => true,
    "samesite" => "Lax"
]);
header("Location: index.php", true, 303);
exit;
Nur für die lokale HTTP-Übung: secure => false. Bei einer Bereitstellung über HTTPS wird secure => true verwendet. Diese Beispiele sind keine Vorlage für eine Anmeldung.

Beim nächsten Request lesen

Erst prüfen, dann verwenden. Ein Cookie ist eine veränderbare Eingabe des Clients – kein vertrauenswürdiger Datenspeicher. HTML-Ausgabe zusätzlich maskieren. [4] [7] [8]

$sprache = "de"; // Standard, falls kein gültiges Cookie ankommt
if (isset($_COOKIE["PHP_demo_sprache"])) {
    if (is_string($_COOKIE["PHP_demo_sprache"])) {
        $wert = $_COOKIE["PHP_demo_sprache"];
        if ($wert === "de" || $wert === "en") {
            $sprache = $wert;
        }
    }
}
// Erst nach der Verarbeitung im HTML ausgeben:
echo htmlspecialchars($sprache, ENT_QUOTES, "UTF-8");

Im Browser löschen

Dasselbe Cookie mit einer Ablaufzeit in der Vergangenheit senden. Ein bloßes unset($_COOKIE[...]) entfernt nur den PHP-Arrayeintrag im laufenden Skript. [1] [2]

// Gleicher Name, Pfad und gegebenenfalls gleiche Domain!
setcookie("PHP_demo_sprache", "", [
    "expires" => time() - 3600, // Vergangenheit = löschen
    "path" => "/PHP_AI_DEMO/PHP_Arbeitsbereich/cookies/demo/",
    "secure" => false,        // nur lokale HTTP-Übung
    "httponly" => true,
    "samesite" => "Lax"
]);
header("Location: index.php", true, 303);
exit;
Welche Cookie-Option bedeutet was?
OptionBedeutung im Beispiel
expiresAblaufzeitpunkt: time() + 3600 bedeutet eine Stunde ab jetzt; nicht „3600“ allein.
pathPassender URL-Bereich. / erfasst alle Pfade dieses Hosts. Kein Windows-Dateipfad und keine Zugriffsberechtigung.
secureBei true für HTTPS-Übertragung vorgesehen. Lokal verwenden wir ausdrücklich HTTP und false.
httponlyVerhindert Cookie-Zugriff über JavaScript. Der Nutzer kann das Cookie trotzdem mit Browserwerkzeugen sehen und ändern.
samesiteLax schränkt das Mitsenden bei seitenübergreifenden Anfragen ein; kein vollständiger Schutz für alle zustandsändernden Aktionen.
domainHier weggelassen: an den setzenden Host gebunden. Beim Setzen und Löschen konsistent bleiben.

Details zu Reichweite und Schutzattributen: [5].

03 / Die Regeln

Diese sechs Dinge müssen sitzen.

1. Verarbeitung vor Ausgabe

setcookie() und header() stehen vor echo, HTML und sonstiger Ausgabe. Auch ein ausgegebener Leerraum oder eine BOM kann stören. Reine PHP-Hilfsdateien ohne schließendes PHP-Tag speichern. Nach der Rückleitung folgt exit. [1] [3]

2. Neuer Header ist nicht neuer Arrayinhalt

Der aktuelle Request bleibt unverändert. Nach Setzen, Ändern oder Löschen erst eine neue Anfrage beobachten. $_COOKIE nicht von Hand befüllen, um eine Speicherung vorzutäuschen. [2]

3. Lebensdauer bewusst wählen

In PHP bedeutet expires => 0 ein Cookie für die Browser-Sitzung, nicht „sofort löschen“. Browser können solche Cookies beim Wiederherstellen einer Sitzung behalten. Zum Testen eines festen Ablaufs eine kurze Zeit verwenden und danach neu laden. [1] [4]

4. Name und Gültigkeitsbereich müssen passen

Ändern und Löschen brauchen denselben Cookie-Namen, denselben Pfad und eine gegebenenfalls gesetzte Domain. Im Paket wird der URL-Ordner automatisch ermittelt; in Aufgabe 8 wird der Bereich bewusst eingeschränkt. [4]

5. Der Client darf fehlen oder lügen

Jeden Eintrag mit isset(), Texttyp und erlaubtem Inhalt prüfen. Ohne gültigen Wert einen Standard verwenden. HttpOnly ist kein Manipulationsschutz gegenüber dem Nutzer. Keine Passwörter, Rollen oder Zugriffsrechte als vertrauenswürdige Cookie-Werte behandeln. [4] [5] [7]

6. Erst prüfen, dann den Zustand ändern

In unseren Übungen werden bei einem Formfehler keine Cookies verändert. Gültige neue Eingaben gehen mit der Fehlermeldung zurück; ungültige Felder bleiben leer. Ältere gespeicherte Einstellungen sind davon getrennt.
