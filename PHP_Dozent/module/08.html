Baustein 08 · Formulare

Ein Formular hat ein Übermittlungsziel

form gruppiert Eingabeelemente. action bezeichnet die Verarbeitung, method die HTTP-Methode. HTML allein implementiert keine Datenbankverarbeitung.

  • Im Grundlagenbereich zeigen die Demos eine ausdrücklich lokale Vorschau.
  • In Modul 11 werden Daten tatsächlich an PHP übergeben.
  • Ein submit-Button löst die Übermittlung des zugeordneten Formulars aus.
Beispiel lesen
<form action="auswerten.php" method="post">
  <!-- Hier stehen die Eingabeelemente. -->
  <button type="submit">Anfrage senden</button>
</form>
Merke / Beobachtung: auswerten.php muss später als reale Verarbeitung vorhanden sein.

Baustein 08 · Formulare

Label, ID und Name erfüllen verschiedene Rollen

label beschriftet. for und id stellen eine ausdrückliche Zuordnung her. name benennt den zu übermittelnden Feldwert.

  • Eine passende ID allein ersetzt kein name.
  • Die Beschriftung bleibt auch dann sichtbar, wenn ein Feld ausgefüllt ist.
  • Verwende eindeutige IDs für einzelne Felder.
Beispiel lesen
<label for="ziel">Reiseziel</label>
<input id="ziel" name="reiseziel" type="text">
Merke / Beobachtung: Beschriftungszuordnung: ziel. Übermittlungsname: reiseziel.

Baustein 08 · Formulare

Radio oder Checkbox?

Radio-Buttons derselben Gruppe teilen einen name-Wert. Checkboxen erlauben voneinander unabhängige Auswahlmöglichkeiten.

  • Für Hotel ja/nein ist genau eine Option sinnvoll.
  • Jede Radio-Option hat eigenen Wert und eindeutige ID.
  • Im Kurs verwenden unabhängige Wünsche unterschiedliche Feldnamen.
Beispiel lesen
<label><input type="radio" name="hotel" value="ja"> Ja</label>
<label><input type="radio" name="hotel" value="nein"> Nein</label>
<label><input type="checkbox" name="transfer" value="ja"> Transfer</label>
Merke / Beobachtung: Die beiden Hotelwerte gehören zusammen, der Transfer ist unabhängig.

Baustein 08 · Formulare

Auswahl und mehrzeiliger Text

select enthält option-Elemente. textarea nimmt einen mehrzeiligen Inhalt auf.

  • Bei einer Option können sichtbare Beschriftung und value getrennt sein.
  • Der Vorbelegungstext einer textarea steht zwischen ihren Tags.
  • rows legt eine Ausgangshöhe fest, nicht die Bedeutung des Inhalts.
Beispiel lesen
<label for="ort">Ziel</label>
<select id="ort" name="ziel">
  <option value="PAR">Paris</option>
  <option value="ROM">Rom</option>
</select>
<textarea name="hinweise" rows="3">Bitte beachten …</textarea>
Merke / Beobachtung: Bei Paris wird hier der Wert PAR übermittelt.

Baustein 08 · Formulare

Button-Typen ausdrücklich festlegen

submit sendet, reset setzt die Formularwerte auf ihre Ausgangswerte zurück und button benötigt für eigene Aktionen zusätzliche Logik.

  • Eine Schaltfläche namens „Absenden“ mit type button ist ohne Logik keine Verarbeitung.
  • Korrektur K11: Die Zuordnung zu einem Formular muss nicht immer durch räumliche Verschachtelung erfolgen; unsere Grundlagenbeispiele verschachteln bewusst.
  • Ungewolltes Zurücksetzen kann Eingaben verwerfen.
Beispiel lesen
<button type="submit">Anfrage senden</button>
<button type="reset">Ausgangswerte</button>
<button type="button">Ohne eigene Aktion</button>
Merke / Beobachtung: Die sichtbare Aufschrift ersetzt nicht den Button-Typ.

Baustein 08 · Formulare

Vorhersagen, ausfüllen und prüfen

Lies zuerst Namen und Werte im Quelltext. Fülle dann das Formular aus und vergleiche die lokale Vorschau.

  • Nicht ausgewählte Checkboxen erscheinen nicht als angekreuzte Werte.
  • Prüfe Radio-Gruppierung, Auswahlwerte und Label-Klick.
  • Eine lokale Vorschau ist weder Serverübermittlung noch Buchung.
Beispiel lesen
name="ziel" + value="PAR" → ziel: PAR
Merke / Beobachtung: Für die Vorschau ist kleine separate Werkzeuglogik vorhanden; sie ist kein neues JavaScript-Lernkapitel.
