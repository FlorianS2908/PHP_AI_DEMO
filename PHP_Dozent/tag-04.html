Kurz erklärt

Arbeite zuerst mit nur ein oder zwei Feldern. Die vorhandenen Alltagsformulare zeigen den Ablauf mit getrennten Dateien für Anzeige, Verarbeitung und Funktionen. Baue erst danach die kleine Variante deines KI-Projekts.

Für die heutige lokale Übung können harmlose kurze Rückmeldungen mit http_build_query im Query-Teil der Rücksprung-URL stehen. Sensible Daten gehören dort nicht hinein. Tag 5 führt Sessions als Alternative für Rückmeldungen und Entwürfe ein.

Superglobale Arrays
$_GET enthält Query-Parameter. $_POST enthält hier die Daten eines gewöhnlichen HTML-POST-Formulars. JSON-Nutzdaten landen nicht automatisch in $_POST; JSON-APIs sind kein Pflichtstoff.
isset und empty
isset prüft, ob ein Eintrag existiert und nicht null ist. empty gilt auch für 0 und "0" als wahr. Ob null oder 0 fachlich erlaubt ist, entscheidet die Aufgabe.
Validierung
Prüfe erst Existenz und erwarteten Datentyp, dann Inhalt und Wertebereich. Auch ein erwartetes Textfeld kann manipuliert als Array ankommen. trim darf erst auf einen String angewendet werden.
Maskierung
htmlspecialchars mit ENT_QUOTES und UTF-8 macht Text für die hier verwendete HTML-Ausgabe geeignet. Es ersetzt keine fachliche Prüfung und gilt nicht automatisch für JavaScript-, CSS- oder SQL-Kontexte.
Fehlerliste
Ein assoziatives Array kann Feldnamen auf Fehlermeldungen abbilden. Zeige konkrete Hinweise und erhalte die gültigen Eingaben, statt alles zu löschen.
POST/Redirect/GET
Nach der Verarbeitung veranlasst eine 303-Antwort einen neuen GET-Aufruf. header muss vor jeder Ausgabe stehen; danach beendet exit das Skript. $_POST wird nicht automatisch in den GET-Aufruf übernommen.

Kleines Beispiel lesen

$fehler = [];
$ziel = "";
if (!isset($_POST["ziel"]) || !is_string($_POST["ziel"])) {
    $fehler["ziel"] = "Bitte einen Zielort als Text senden.";
} else {
    $ziel = trim($_POST["ziel"]);
    if ($ziel === "") {
        $fehler["ziel"] = "Bitte einen Zielort eintragen.";
    }
}
// Bei der späteren HTML-Ausgabe:
echo htmlspecialchars($ziel, ENT_QUOTES, "UTF-8");

Erst die Wirkung vorhersagen, dann ausführen oder im Browser untersuchen. Das Beispiel erklärt ein Prinzip; es ist keine Lösung der folgenden Aufgabe.

Selbst umsetzen

Wähle eine kleine Alltagsaufgabe und ergänze die fehlende Verarbeitung. Prüfe Direktaufruf ohne POST, fehlendes Feld, Leerzeichen, gültigen Text, den Wert "0" und eine Array-Eingabe. Gib fremdes HTML als Text aus. Vergleiche nach dem Absenden den POST und den folgenden GET. Halte Eingabe, Soll, Ist und Korrektur schriftlich fest.

Abgabe: eigene Dateien, kurze Erklärung und mindestens ein Normal-, Fehl- und Grenzfall mit Soll/Ist-Vergleich.

Hinweise für die Lehrkraft

Ein kleiner belastbarer Datenweg zählt mehr als ein umfangreiches Formular. Serverseitige Validierung sichtbar schreiben lassen. Die großen fünf KI-Musterlösungen nur als spätere Vergleichsreferenz nutzen; keine vollständige Nachimplementierung aller fünf Projekte verlangen.
