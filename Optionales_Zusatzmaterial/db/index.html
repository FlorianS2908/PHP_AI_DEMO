00 / In XAMPP starten

Einmal einrichten

Den Ordner PHP_Datenbank nach C:\xampp\htdocs entpacken. Apache und den MySQL-Dienst starten. In phpMyAdmin die Datei datenbank.sql einmal importieren. Danach die Zugangsdaten in config.php prüfen.

http://localhost/PHP_Datenbank/index.html

Voraussetzung: PHP 8 mit pdo_mysql, mbstring und Sessions; MySQL oder MariaDB. Die mitgelieferten Zugangsdaten sind eine lokale Vorlage: Host 127.0.0.1, Port 3306, root, leeres Passwort. Abweichende Werte in config.php ändern. [1] [10]

01 / Wer macht was?

Drei Orte auseinanderhalten

OrtAufgabe
BrowserZeigt Formular und HTML-Tabelle. Sendet neue Eingaben per POST.
PHP auf dem ServerPrüft Eingaben, spricht die DB über PDO an, erzeugt Person-Objekte und HTML.
MySQL / MariaDBSpeichert die Datensätze unabhängig vom einzelnen PHP-Aufruf.

Ein PHP-Objekt ist kein Datenbankeintrag. new Person(...) erzeugt hier nur ein Objekt im Arbeitsspeicher. Erst das ausdrückliche INSERT schreibt in die Datenbank. Beim nächsten Lesen entstehen neue Objekte aus den gespeicherten Zeilen.

In dieser Anwendung bleibt Person.php ein Datenträger. Sie enthält weder SQL noch HTML. Technische Bausteine: [1]–[4].

Unsere einzige Tabelle: personen

SpalteTypAufgabe
idINT, Primärschlüssel, AUTO_INCREMENTDie Datenbank vergibt die ID. Kein Eingabefeld.
vornameVARCHAR(50), NOT NULLVorname als Text.
nachnameVARCHAR(50), NOT NULLNachname als Text.

Die PHP-Prüfung verlangt zusätzlich ausgefüllte Texte mit höchstens 50 Zeichen. NOT NULL allein ist keine Prüfung auf einen leeren String. Die Beispieldaten sind Mia Müller, Noah Schneider und Lea Özdemir. ID-Vergabe: [8].

02 / Lesen

Aus einer DB-Zeile wird eine Person

SELECT → Array-Zeile → Person-Objekt → Getter → HTML

$abfrage = $pdo->query(
    "SELECT id, vorname, nachname FROM personen ORDER BY id"
);
$personen = [];

while ($zeile = $abfrage->fetch(PDO::FETCH_ASSOC)) {
    $personen[] = new Person(
        (int) $zeile["id"],
        $zeile["vorname"],
        $zeile["nachname"]
    );
}

query() führt hier die feste Abfrage aus. fetch(PDO::FETCH_ASSOC) liefert die nächste Zeile als Array mit Spaltennamen als Schlüsseln. Am Ende kommt false; die Schleife endet. In jedem Durchlauf erzeugen wir ein neues Objekt. [2]

Die kleine Person-Klasse ansehen
<?php
declare(strict_types=1);

// Eine Person ist hier ein Datenträger: kein SQL, keine HTML-Ausgabe.
class Person
{
    private int $id;
    private string $vorname;
    private string $nachname;

    public function __construct(int $id, string $vorname, string $nachname)
    {
        $this->id = $id;
        $this->vorname = $vorname;
        $this->nachname = $nachname;
    }

    public function getId(): int
    {
        return $this->id;
    }

    public function getVorname(): string
    {
        return $this->vorname;
    }

    public function getNachname(): string
    {
        return $this->nachname;
    }
}

Die Typen int und string beschreiben ID und Texte. Der Konstruktor übernimmt die Werte; die Getter geben sie zurück. Es gibt keine automatische Speicherung.

Dann nur noch die Getter ausgeben

<?php foreach ($personen as $person) { ?>
    <tr>
        <td><?= $person->getId() ?></td>
        <td><?= html($person->getVorname()) ?></td>
        <td><?= html($person->getNachname()) ?></td>
    </tr>
<?php } ?>

Das vorbereitete html() verwendet htmlspecialchars(). Auch gespeicherte Texte müssen bei der Ausgabe maskiert werden. Die ID ist hier bereits eine ganze Zahl. [6]

03 / Schreiben

Erst prüfen. Dann INSERT.

Das Formular sendet vorname und nachname an speichern.php. Jeder Eintrag wird vor dem Auslesen mit isset() und is_string() geprüft. Danach folgen trim(), Pflichtfeld- und Längenprüfung.

Sind Angaben falsch, wird nichts eingefügt. Beide Felder werden geprüft; gültige neue Eingaben bleiben nach der Rückleitung erhalten. Die bekannte Session transportiert nur Meldungen und vorübergehende Formwerte.

$pdo = verbindeDatenbank();
// Platzhalter statt zusammengesetzter SQL-Zeichenkette.
$anweisung = $pdo->prepare(
    "INSERT INTO personen (vorname, nachname) VALUES (:vorname, :nachname)"
);
$anweisung->execute([
    "vorname" => $werte["vorname"],
    "nachname" => $werte["nachname"]
]);

prepare() erhält den SQL-Befehl mit Platzhaltern. execute() erhält die Werte getrennt davon. Platzhalter werden nicht in zusätzliche SQL-Anführungszeichen gesetzt. Benutzereingaben werden nicht in den SQL-Text hineinkopiert. [3] [4]

$_SESSION["erfolg"] = "Die Person wurde gespeichert.";
header("Location: index.php", true, 303);
exit;

Die 303-Antwort löst einen neuen GET-Aufruf aus. Er liest die aktuelle Tabelle. F5 auf dieser GET-Seite führt kein INSERT aus; bewusstes erneutes Absenden bleibt eine neue Schreibaktion. [7]

05 / Die wenigen wichtigen Regeln

Für diese Anwendung merken

SQL und Werte trennen. Nutzereingaben gehören in Parameter, nicht per Verkettung in SQL. [3]

Validierung ist nicht Ausgabe-Maskierung. Die Eingabe in PHP prüfen. Unmaskierte gültige Texte speichern. Erst bei der HTML-Ausgabe html() verwenden. [6]

Fehler abfangen. Das vorbereitete try/catch fängt PDO-Ausnahmen ab. Im Browser erscheint ein Hinweis; technische Details stehen nur im Serverprotokoll. [5]

Vor einer Rückleitung nichts ausgeben. PHP-Verarbeitung vor HTML; nach header() beenden. Im Paket wird der bekannte Session-Rückweg verwendet. [7]

Die PDO-Verbindung als kleiner Baustein
$pdo = new PDO(
    "mysql:host=127.0.0.1;port=3306;dbname=PHP_personen;charset=utf8mb4",
    $benutzer,
    $passwort,
    [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
     PDO::ATTR_EMULATE_PREPARES => false]
);

Im Paket liegen die Zugangsdaten in config.php. PDO wird in db.php erzeugt. Der Treiber heißt auch bei MariaDB mysql. [1] [10]

Vorgegebener Rahmen, kein neuer Lernstoff

Session-Einstellungen, HTML-Helper und ein versteckter Formulartoken sind vorbereitet. Die Session enthält keine dauerhafte Personenliste. Der Token ist ein zusätzlicher Schutz für POST-Formulare und kein drittes Personendatum. [11]

Nur auf localhost mit erfundenen Daten verwenden. Kein Login, keine Rechteverwaltung, kein Produktivsystem. Die Datenbankzugangsdaten gehören nicht ins HTML.
